# Strict-only Optimizer Equivalence Facts Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** 让 optimizer logical properties 的 `equivalence_classes` 只承载普通 `=` 推导出的 strict 等价事实，并让 multi-join reorder 从 root logical properties 读取权威等价类。

**Architecture:** 保留现有 `EquivalenceClasses` 单 store，不引入 `NullSafe` store。先把共享 collector 重命名为 `collect_strict_column_equalities`，再把 logical props 派生、`equivalence_predicate` 和 reorder flatten 全部切到 strict-only 语义；reorder 的 raw predicates 仍用于 join edge/mask，只替换 transitive class 来源。

**Tech Stack:** Rust optimizer code under `src/sql/optimizer/**`, SQL golden runner under `tests/sql-test-runner`, documentation under `docs/design/**`.

---

```rust
pub(crate) fn collect_strict_column_equalities(
    scalars: &ScalarArena,
    expr: ScalarId,
) -> Vec<(ColumnId, ColumnId)> {
    let mut out = Vec::new();
    collect_strict_column_equalities_inner(scalars, expr, &mut out);
    out
}

fn collect_strict_column_equalities_inner(
    scalars: &ScalarArena,
    expr: ScalarId,
    out: &mut Vec<(ColumnId, ColumnId)>,
) {
    match scalars.node(expr) {
        ScalarNode::Nested(inner) => collect_strict_column_equalities_inner(scalars, *inner, out),
        ScalarNode::BinaryOp {
            left,
            op: BinOp::And,
            right,
        } => {
            collect_strict_column_equalities_inner(scalars, *left, out);
            collect_strict_column_equalities_inner(scalars, *right, out);
        }
        ScalarNode::BinaryOp {
            left,
            op: BinOp::Eq,
            right,
        } => {
            if let (Some(left_id), Some(right_id)) = (
                column_id_from_scalar(scalars, *left),
                column_id_from_scalar(scalars, *right),
            ) {
                out.push((left_id, right_id));
            }
        }
        _ => {}
    }
}
```

Do not keep a public `collect_column_equalities` wrapper. The compile errors in other modules are intentional and handled in Task 2.

```rust
fn project_root_equi_classes(
    memo: &mut Memo,
    root: GroupId,
    atoms: &[GroupId],
    atom_cols: &[HashSet<ColumnId>],
) -> Vec<EquiClass> {
    let classes: Vec<_> = memo
        .groups
        .get(root)
        .and_then(|group| group.logical_props.as_ref())
        .map(|props| props.equivalence_classes.classes().to_vec())
        .unwrap_or_default();

    let mut out = Vec::new();
    for class in &classes {
        let mut reps = Vec::new();
        for (atom_idx, atom) in atoms.iter().enumerate() {
            let rep_column = class
                .iter()
                .filter(|column_id| atom_cols[atom_idx].contains(column_id))
                .filter_map(|column_id| atom_output_column(memo, *atom, column_id))
                .min_by_key(|column| column.column_id);
            if let Some(column) = rep_column {
                let scalar = intern_output_column_ref(memo, &column);
                reps.push((atom_idx, scalar));
            }
        }
        if reps.len() >= 2 {
            out.push(EquiClass::new(class.iter().collect(), reps));
        }
    }
    out
}

fn atom_output_column(
    memo: &Memo,
    atom: GroupId,
    column_id: ColumnId,
) -> Option<crate::sql::common::OutputColumn> {
    memo.groups
        .get(atom)
        .and_then(|group| group.logical_props.as_ref())
        .and_then(|props| {
            props
                .output_columns
                .iter()
                .find(|column| column.column_id == column_id)
                .cloned()
        })
}

fn intern_output_column_ref(
    memo: &mut Memo,
    column: &crate::sql::common::OutputColumn,
) -> ScalarId {
    memo.scalars
        .remember_source_column_display(column.column_id, None, column.name.clone());
    memo.scalars.intern(
        ScalarNode::ColumnRef(column.column_id),
        column.data_type.clone(),
        column.nullable,
    )
}
```

```rust
        let root = copy_in_join_tree(&mut memo, &tree, &Map::new());
        let mut root_props = LogicalProperties::new(
            vec![out_col(1), out_col(2), out_col(3), out_col(4)],
            50.0,
        );
        root_props.equivalence_classes.merge_pair(ColumnId::new_for_test(1), ColumnId::new_for_test(3));
        root_props.equivalence_classes.merge_pair(ColumnId::new_for_test(2), ColumnId::new_for_test(4));
        memo.groups[root].logical_props = Some(root_props);

        let graph = flatten_join_chain(&mut memo, root).expect("3-atom chain flattens");

        assert!(
            !graph.equi_classes.iter().any(|class| class.straddles(0b010, 0b100)),
            "B-C cut must not be connected without a root strict class spanning both atoms"
        );
    }
```

This test models the strict-only result of an atom-internal `<=>`: the null-safe internal fact is absent from root strict facts, so the projected classes remain `{a1,b}` and `{a2,c}`.

## Implementation Notes

- `LogicalProperties.equivalence_classes` remains the single strict store. Do not introduce `EquivalenceKind`, `EquivalenceFacts`, or a null-safe store.
- `EqForNull` can still be used by physical hash join execution and other actual-predicate consumers. The strict store simply does not expose it.
- `equivalence_predicate.rs::join_column_pairs` intentionally becomes strict-only. Cross `<=>` join literal propagation is a conservative optimization loss accepted by the spec.
- `flatten_join_chain` still needs `raw_predicates` for relation masks and predicate materialization. Only `equi_classes` source changes.
- Representative `ColumnRef` scalars in reorder must be interned from atom `OutputColumn` metadata. Do not reuse raw predicate operands for representatives.
- CTE consume remains a boundary. Do not add inheritance through `LogicalCTEConsume` / `PhysicalCTEConsume` in this implementation.
